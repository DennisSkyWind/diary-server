# LLM-Wiki vs 日记系统对比分析与优化方案

## 一、LLM-Wiki 核心设计原理

### 1.1 核心理念
> "Knowledge compounds over time — the more you use it, the smarter it gets."
> 知识随时间复合增长 — 使用越多，系统越智能。

### 1.2 设计模式（Karpathy模式）
```
┌─────────────────────────────────────────────────────────┐
│  Raw Sources (immutable)                                │
│  原始文件不可变，保持数据完整性                           │
├─────────────────────────────────────────────────────────┤
│  Wiki Layer (LLM-maintained)                            │
│  Wiki层由LLM维护，自动生成和更新                          │
├─────────────────────────────────────────────────────────┤
│  Schema Layer (governs behavior)                        │
│  Schema层定义规则和行为                                  │
└─────────────────────────────────────────────────────────┘
```

### 1.3 核心机制

| 机制 | 描述 | 创新点 |
|:-----|:-----|:-----|
| **Research-on-Miss** | 查询时自动研究缺失内容 | 主动扩展知识 |
| **9-Tier Freshness** | live→permanent 9级过期 | 内容生命周期管理 |
| **Self-Maintaining** | 自动lint、去重、升级置信度 | 无需手动维护 |
| **Block References** | `[[page#heading]]` 双链 | 结构化引用 |
| **Backlinks Panel** | 自动检测未链接引用 | 发现隐含关联 |
| **Dataview Query** | frontmatter查询语言 | 结构化数据查询 |
| **Spaced Repetition** | FSRS调度复习 | 知识强化记忆 |
| **Content Gap Analysis** | Dashboard缺口分析 | 发现知识盲区 |

## 四、优化方案

### 4.1 Phase 1: 核心差距修复（高优先级）

#### 4.1.1 Research-on-Miss机制

**设计**：
```python
def research_on_miss(query):
    """
    查询时如果知识库中没有，自动研究并摄入
    """
    # 1. 检查Wiki/日记系统
    result = search_memory(query)
    
    if not result:
        # 2. 自动研究
        research = tavily_search(query)
        
        # 3. 摄入到知识库
        ingest_to_wiki(research)
        
        # 4. 返回结果
        result = format_answer(research)
    
    return result
```

**实施**：
- 在日记系统添加 `/api/research` 端点
- 集成Tavily搜索
- 自动创建Wiki页面保存研究结果

#### 4.1.2 内容新鲜度系统

**设计**：9级过期机制

| 级别 | 名称 | TTL | 适用场景 |
|:---:|:-----|:---:|:---------|
| 1 | live | 15分钟 | 实时数据 |
| 2 | fresh | 1小时 | 今日事件 |
| 3 | recent | 1天 | 每日笔记 |
| 4 | current | 1周 | 常规记录 |
| 5 | stable | 1月 | 稳定知识 |
| 6 | established | 3月 | 建立结论 |
| 7 | mature | 1年 | 成熟知识 |
| 8 | archival | 3年 | 归档内容 |
| 9 | permanent | 永不 | 核心原则 |

**实施**：
- 在frontmatter添加 `freshness: recent`
- 定时任务检查过期内容
- 过期提醒Dashboard

#### 4.1.3 自维护功能

**设计**：
```javascript
// 自维护任务
function self_maintenance() {
  // 1. 检查断裂链接
  lint_broken_links();
  
  // 2. 合并重复内容
  merge_duplicates();
  
  // 3. 升级置信度
  upgrade_confidence();
  
  // 4. 标记过期内容
  flag_stale_content();
  
  // 5. 建议关联
  suggest_relations();
}
```

**实施**：
- 在每日整理任务中添加自维护步骤
- 创建 `/api/maintenance/lint` 端点
- Dashboard显示维护报告

### 4.2 Phase 2: 结构化引用（中优先级）

#### 4.2.1 双链引用系统

**设计**：
```markdown
# 文件A.md

## 核心观点
这是我的观点，参考了 [[文件B#结论]] 的分析。

---

# 文件B.md

## 结论
这是结论部分。

<!-- 自动生成反向链接 -->
**反向链接**: 
- 文件A#核心观点
- 文件C#相关讨论
```

**实施**：
- 解析Markdown中的 `[[file#section]]` 链接
- 自动生成反向链接索引
- 前端显示反向链接面板

#### 4.2.2 Dataview查询语言

**设计**：
```markdown
---
type: note
confidence: high
freshness: recent
tags: [work, diary, tech]
---

## Dataview查询示例

```dataview
SELECT title, type, freshness 
FROM pages 
WHERE confidence = "high" 
AND freshness IN ["recent", "current"]
ORDER BY date DESC
LIMIT 10
```
```

**实施**：
- 解析frontmatter元数据
- 实现查询解析器
- 在页面中嵌入查询结果

## 六、架构升级建议

### 6.1 三层架构重构

```
┌─────────────────────────────────────────────────────────┐
│                   Schema Layer                          │
│  ┌─────────────────────────────────────────────────┐   │
│  │  frontmatter规范:                                │   │
│  │  - type: note/event/task/idea                   │   │
│  │  - confidence: low/medium/high                  │   │
│  │  - freshness: live/fresh/.../permanent          │   │
│  │  - tags: [tag1, tag2]                           │   │
│  │  - relations: [[file1]], [[file2#section]]      │   │
│  └─────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│                   Wiki Layer                            │
│  ┌─────────────────────────────────────────────────┐   │
│  │  LLM维护:                                        │   │
│  │  - 自动分类                                      │   │
│  │  - 自动关联                                      │   │
│  │  - 自动摘要                                      │   │
│  │  - 自动更新freshness                             │   │
│  └─────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│                   Raw Layer                             │
│  ┌─────────────────────────────────────────────────┐   │
│  │  原始Markdown文件（不可变）                       │   │
│  │  只读，所有修改通过Wiki层                         │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### 6.2 数据流设计

```
用户操作 → Wiki层处理 → Raw层存储
                ↓
         Schema验证
                ↓
         知识图谱更新
                ↓
         搜索索引更新
                ↓
         维护任务触发
```

## 七、总结

### 7.1 关键差距

| 差距 | 影响 | 优先级 |
|:-----|:-----|:---:|
| 缺少Research-on-Miss | 知识不能自动扩展 | 🔴 高 |
| 缺少新鲜度机制 | 内容过期无法识别 | 🔴 高 |
| 缺少自维护功能 | 需手动维护知识库 | 🔴 高 |
| 缺少双链引用 | 无法结构化引用 | 🟡 中 |
| 缺少反向链接 | 无法发现隐含关联 | 🟡 中 |
| 缺少Dataview查询 | 无法结构化查询 | 🟡 中 |

### 7.2 核心改进方向

从"文件整理系统"升级为"知识复合增长系统"：

1. **主动获取** - Research-on-Miss自动扩展知识
2. **生命周期** - 新鲜度系统管理内容时效
3. **主动维护** - 自维护减少手动干预
4. **结构化引用** - 双链和反向链接
5. **结构化查询** - Dataview查询语言
